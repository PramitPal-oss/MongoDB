# MongoDB `_id` Field

## Introduction

The `_id` field in a MongoDB document is a unique identifier that serves as the primary key of the document. It is a mandatory field in every MongoDB document, meaning that it cannot be omitted. MongoDB automatically creates and assigns a value to `_id` if it is not explicitly specified during document insertion.

## Characteristics of `_id` Field

1. **Uniqueness**
   - The `_id` field uniquely identifies each document within a collection.
2. **Required Field**
   - Every document must have an `_id` field; it cannot be skipped.
3. **Immutability**
   - Once assigned, the `_id` field cannot be updated.
4. **Auto-Generated by MongoDB**
   - If `_id` is not provided, MongoDB generates an ObjectId automatically.
5. **First Field in a Document**
   - By default, the `_id` field appears as the first field in a document.
6. **Cannot Contain Null Values**
   - The `_id` field must always have a value and cannot be null.

## ObjectId Structure

By default, the `_id` field is of type `ObjectId`, which is a 12-byte identifier composed of:

- **4-byte timestamp** – Represents the creation time (measured in seconds since the Unix epoch).
- **5-byte random value** – Generated once per process.
- **3-byte incrementing counter** – Initialized to a random value and incremented per document.

### Example of an `_id` Field in a Document

```json
{
    "_id": ObjectId("65c9f8b2a2e5f4a7c3d67f20"),
    "name": "John Doe",
    "email": "johndoe@example.com"
}
```

## Custom `_id` Values

Instead of letting MongoDB generate an ObjectId, you can specify a custom `_id` value. This value can be any valid BSON type, such as a string, integer, or UUID.

### Example of a Custom `_id` Value

```json
{
  "_id": "user_12345",
  "name": "Alice",
  "email": "alice@example.com"
}
```

### Example with an Integer `_id`

```json
{
  "_id": 1001,
  "product": "Laptop",
  "price": 1200
}
```

## Considerations for Using `_id`

1. **Indexing**

   - The `_id` field is automatically indexed, making lookups faster.

2. **Uniqueness Constraint**

   - You cannot insert multiple documents with the same `_id` in a collection.

3. **Performance Considerations**
   - Using sequential numeric or string-based `_id` values may improve performance in some scenarios.
   - However, ObjectId ensures uniqueness and distributed generation without collisions.

## Querying by `_id`

Since `_id` is indexed by default, querying by `_id` is efficient.

### Example Query to Find a Document by `_id`

```javascript
db.collection.find({ _id: ObjectId('65c9f8b2a2e5f4a7c3d67f20') });
```

### Example Query with a Custom `_id`

```javascript
db.collection.find({ _id: 'user_12345' });
```

## Conclusion

The `_id` field is a crucial aspect of MongoDB documents, ensuring uniqueness and efficient querying. While ObjectId is the default, custom `_id` values can be used based on application needs. Understanding how `_id` works helps in designing robust MongoDB schemas.
