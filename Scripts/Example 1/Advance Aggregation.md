# 🧩 MongoDB Database Schema Overview

Your dataset represents an **e-commerce ecosystem**, consisting of the following main collections:

```
sellers
 ├── products
 │    ├── reviews
 │    │    ├── reviewer (customer reference)
 │    │    ├── rating
 │    │    └── comment
 │    └── category
 ├── sellerDetails
 │    ├── region
 │    ├── storeType
 │    ├── rating
 │    └── establishedYear
 ├── customers
 │    ├── demographics
 │    ├── purchaseHistory
 │    │    ├── orderId
 │    │    ├── totalAmount
 │    │    └── productsPurchased
 │    │         ├── productId
 │    │         ├── quantity
 │    │         └── price
 └── analytics (derived collections for orders, reviews, etc.)
```

---

## 🧱 1. **sellers** Collection

Each document represents one seller (store or merchant).

```js
{
  _id: ObjectId,
  sellerId: String,
  name: String,
  email: String,
  phone: String,
  active: Boolean,
  joinedDate: ISODate,
  sellerDetails: {
    region: String,        // e.g. "North", "South", "West"
    storeType: String,     // e.g. "Electronics", "Fashion", etc.
    rating: Number,        // avg seller rating
    establishedYear: Number
  },
  products: [ObjectId],    // references to products collection
  customers: [ObjectId],   // references to customers who bought from this seller
  totalRevenue: Number,    // derived total
  totalProducts: Number
}
```

🔗 **Relationships**

- `sellers.products[]` → `products._id`
- `sellers.customers[]` → `customers._id`

---

## 📦 2. **products** Collection

Each product belongs to one seller and one category.
Contains nested reviews.

```js
{
  _id: ObjectId,
  productId: String,
  name: String,
  description: String,
  category: String,          // e.g. "Electronics", "Fashion"
  price: Number,
  stock: Number,
  createdAt: ISODate,
  updatedAt: ISODate,
  sellerId: ObjectId,        // reference to sellers._id
  active: Boolean,
  averageRating: Number,
  totalReviews: Number,
  reviews: [
    {
      reviewId: ObjectId,
      reviewerId: ObjectId,  // reference to customers._id
      rating: Number,        // 1–5
      comment: String,
      createdAt: ISODate
    }
  ]
}
```

🔗 **Relationships**

- `products.sellerId` → `sellers._id`
- `products.reviews.reviewerId` → `customers._id`

---

## 👤 3. **customers** Collection

Each customer may have made multiple purchases and written reviews.

```js
{
  _id: ObjectId,
  customerId: String,
  name: String,
  email: String,
  phone: String,
  gender: String,             // "Male", "Female", "Other"
  city: String,
  region: String,
  joinedDate: ISODate,
  demographics: {
    age: Number,
    income: Number,
    loyaltyLevel: String,     // "Bronze", "Silver", "Gold", "Platinum"
  },
  purchaseHistory: [
    {
      orderId: ObjectId,      // reference to orders._id
      totalAmount: Number,
      purchasedAt: ISODate,
      productsPurchased: [
        {
          productId: ObjectId,
          quantity: Number,
          price: Number
        }
      ]
    }
  ],
  reviewsGiven: [ObjectId],   // references to product.reviews.reviewId
  averageRatingGiven: Number
}
```

🔗 **Relationships**

- `customers.purchaseHistory.productsPurchased.productId` → `products._id`
- `customers.reviewsGiven[]` → `products.reviews.reviewId`

---

## 🧾 4. **orders** Collection

This represents actual transactions.

```js
{
  _id: ObjectId,
  orderId: String,
  customerId: ObjectId,      // ref → customers._id
  sellerId: ObjectId,        // ref → sellers._id
  products: [
    {
      productId: ObjectId,   // ref → products._id
      quantity: Number,
      price: Number
    }
  ],
  totalAmount: Number,
  paymentMethod: String,     // "Credit Card", "UPI", "Cash", etc.
  orderStatus: String,       // "Pending", "Shipped", "Delivered", "Cancelled"
  createdAt: ISODate,
  deliveredAt: ISODate
}
```

🔗 **Relationships**

- `orders.customerId` → `customers._id`
- `orders.sellerId` → `sellers._id`
- `orders.products.productId` → `products._id`

---

## ⭐ 5. **reviews** Collection (optional extracted version)

Even though `reviews` are embedded inside `products`,
you may also keep a separate **reviews** collection for easier aggregation.

```js
{
  _id: ObjectId,
  reviewId: String,
  reviewerId: ObjectId,     // ref → customers._id
  productId: ObjectId,      // ref → products._id
  sellerId: ObjectId,       // ref → sellers._id
  rating: Number,
  comment: String,
  createdAt: ISODate
}
```

🔗 **Relationships**

- `reviews.reviewerId` → `customers._id`
- `reviews.productId` → `products._id`
- `reviews.sellerId` → `sellers._id`

---

## 📊 6. **categories** Collection (optional)

If categories are separated from products:

```js

  categoryId: String,
  name: String,
  description: String,
  totalProducts: Number,
  averagePrice: Number,
  averageRating: Number
}
```

🔗 **Relationships**

- `categories.name` ↔ `products.category`

# 🔗 RELATIONSHIP SUMMARY (like ER diagram)

```
CUSTOMER
 ├── purchaseHistory.productsPurchased.productId → PRODUCT
 ├── reviewsGiven.reviewId → REVIEW
 └── region, demographics, loyaltyLevel → analytics fields

SELLER
 ├── products[] → PRODUCT
 ├── customers[] → CUSTOMER
 └── sellerDetails → metadata

PRODUCT
 ├── sellerId → SELLER
 ├── category → CATEGORY
 └── reviews.reviewerId → CUSTOMER

ORDER
 ├── customerId → CUSTOMER
 ├── sellerId → SELLER
 └── products[].productId → PRODUCT

REVIEW
 ├── reviewerId → CUSTOMER
 ├── productId → PRODUCT
 └── sellerId → SELLER
```
